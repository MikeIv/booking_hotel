## Компоненты

### Booking.vue

Основной компонент формы поиска номеров.

📄 [Документация компонента Booking](./components/Booking.md)

**Краткое описание:**
- Форма поиска номеров с выбором дат, гостей и промокода
- Интеграция с `bookingStore` для управления состоянием
- Автоматическая навигация на страницы результатов поиска
- Валидация данных перед отправкой запроса

### Card.vue

Компонент карточки номера для отображения в результатах поиска.

📄 [Документация компонента Card](./components/Card.md)

**Краткое описание:**
- Отображение информации о номере (фотографии, характеристики, цены)
- Поддержка вариантов номеров с разными типами кроватей
- Выбор типа кровати и переход к выбору тарифа
- Интеграция с `bookingStore` для управления состоянием
- Автоматический выбор подходящего варианта номера

### GuestsSelector.vue

Компонент селектора для выбора количества номеров, взрослых и детей.

📄 [Документация компонента GuestsSelector](./components/GuestsSelector.md)

**Краткое описание:**
- Выбор количества номеров (от 1 до 5)
- Указание количества взрослых и детей в каждом номере
- Задание возраста каждого ребенка (от 0 до 12 лет)
- Автоматическая нормализация данных
- Поддержка legacy формата данных для обратной совместимости
- Интеграция с `bookingStore` через v-model

## Как использовать документацию

1. **Для разработчиков:** Используйте документацию для понимания структуры компонентов, их зависимостей и способов использования.

2. **Для новых участников команды:** Начните с изучения основных компонентов, таких как `Booking.vue`, чтобы понять архитектуру приложения.

3. **При добавлении новых компонентов:** Создавайте соответствующие файлы документации в директории `components/`.

## Формат документации

Каждый файл документации компонента должен содержать:

- **Описание** - краткое описание назначения компонента
- **Расположение** - путь к файлу компонента
- **Зависимости** - используемые stores, composables, компоненты, типы
- **Структура компонента** - описание функциональности (script, template)
- **Использование** - примеры использования
- **Состояния** - описание различных состояний компонента
- **Валидация** - правила валидации (если применимо)
- **Примечания** - дополнительная важная информация

**Важно:** Документация компонентов фокусируется на функциональности, а не на стилях. Подробное описание системы стилей находится в [разделе "Стили"](#стили) этого файла.

## Стили

Проект использует единую систему стилей на основе SCSS с CSS Modules.

### Единицы измерения

Все размеры в проекте указываются в единицах `rem` для обеспечения масштабируемости и доступности. Для конвертации пикселей в rem используется функция `rem()`:

```scss
@function rem($px) {
  $base-font-size: 16; // 16px = 1rem
  @return math.div($px, $base-font-size) * 1rem;
}
```

**Пример использования:**
```scss
padding: rem(14) rem(12); // 14px и 12px конвертируются в rem
```

### CSS переменные (Custom Properties)

Проект использует CSS переменные для цветов, размеров и других значений, что обеспечивает централизованное управление дизайн-системой.

#### Цвета

Цвета определены в `app/assets/styles/variables/_colors.scss` и доступны через CSS переменные:

**Основные цвета:**
- `--primary` - основной цвет (#bf9d7c)
- `--secondary` - вторичный цвет (#686062)
- `--success` - цвет успеха (#7dbf8a)
- `--info` / `--ui-bgAccent` - акцентный цвет (#a02525)

**Текст:**
- `--a-text-white` - белый текст
- `--a-text-primary` - основной цвет текста
- `--a-text-light` - светлый текст (#a9a9a9)
- `--a-text-dark` - темный текст
- `--a-text-accent` - акцентный цвет текста

**Фон:**
- `--a-whiteBg` - белый фон
- `--a-blackBg` - черный фон
- `--a-mainBg` - основной фон (#e5e5e5)
- `--a-primaryBg` - фон основного цвета
- `--a-btnAccentBg` - фон акцентной кнопки

**Границы:**
- `--a-border` - стандартная граница
- `--a-border-primary` - граница основного цвета
- `--a-border-accent` - акцентная граница

**Палитры цветов:**
Проект также включает полные палитры для primary, secondary, success и accent цветов с оттенками от 50 до 950 (например, `--ui-color-primary-50`, `--ui-color-primary-100`, и т.д.).

#### Размеры экранов (Breakpoints)

Размеры экранов определены в `app/assets/styles/variables/resolutions.scss`:

```scss
$mobile: 576px;
$tabletMin: 670px;
$tablet: 768px;
$tabletMax: 992px;
$desktopMin: 1024px;
$desktopMedium: 1366px;
$desktop: 1642px;
$desktopMax: 1920px;
```

**Использование в медиа-запросах:**
```scss
@media (min-width: #{size.$tablet}) {
  // стили для планшетов и выше
}

@media (min-width: #{size.$desktopMin}) {
  // стили для десктопов и выше
}
```

### Импорт SCSS переменных

При работе со стилями компонентов необходимо правильно импортировать переменные из системы дизайна.

#### Импорт breakpoints (resolutions)

```scss
@use "~/assets/styles/variables/resolutions" as size;

@media (min-width: #{size.$tablet}) {
  // стили для планшетов
}

@media (min-width: #{size.$desktopMin}) {
  // стили для десктопов
}
```

#### Импорт z-index

Z-index значения определены в `app/assets/styles/variables/_z-index.scss` и доступны через функцию `z()`.

```scss
@use "~/assets/styles/variables/z-index" as z;

.modal {
  z-index: z.z("modal", "overlay"); // Вложенное значение
}

.dropdown {
  z-index: z.z("dropdown"); // Простое значение
}

.intro {
  z-index: z.z("intro");
}
```

**Доступные значения z-index:**
- `modal.overlay`, `modal.content`, `modal.nav-menu`
- `dropdown`
- `header`
- `footer`
- `booking-label`, `booking-summary`
- `intro`
- `default`
- `behind`

**Важно:** Используйте `@use` вместо `@import` для импорта SCSS модулей. Это обеспечивает правильную изоляцию и предотвращает конфликты.

### Иконки

Проект использует `@nuxt/icon`. Базовая коллекция иконок хранится в `app/assets/icons` и подключается с префиксом `i-`.

#### Источники иконок в проекте

- **Основной источник (UI):** `app/assets/icons` через `<UIcon name="i-..." />`
- **Внешние наборы (ограниченно):** `heroicons`, `mdi`, `simple-icons`
- **Не-UI SVG вне коллекции иконок:** `app/assets/images`, `public/images` (логотипы, декоративные или контентные графики)

#### Стандарт дизайн-системы для UI-иконок

- Один основной набор для интерфейса: `app/assets/icons`
- Разрешенные размеры для UI-иконок: `16`, `20`, `24`
- Единый стиль для UI-иконок: `outline/stroke`
- Запрещено смешивать `stroke` и `filled` в рамках одной UI-семьи
- Цвет иконки задается через `currentColor`

#### Категории и правила

- **UI icons:** строго по стандарту (`16/20/24`, единый стиль, `currentColor`)
- **Brand/Social/Doc:** отдельная категория (Telegram, VK, PDF) допускается как брендовая
- **Illustrative:** декоративные SVG не входят в UI-набор и не нормализуются под `16/20/24`

#### Размещение в Figma

Коллекцию иконок необходимо вести в библиотеке дизайн-системы:

- `Design System -> Foundations -> Icons`
- Внутри обязательный фрейм `Used in Project` (все фактически используемые иконки из кода)
- Отдельные секции: `16`, `20`, `24`
- В продуктовых макетах использовать инстансы из библиотеки, а не локальные SVG-вставки

Детальная инвентаризация и текущие статусы: [docs/icons-audit.md](./icons-audit.md).

#### Применение в коде

```vue
<template>
  <UIcon name="i-calendar" class="calendarIcon" />
  <UIcon name="i-phone" :class="$style.phoneIcon" />
</template>
```

Внешние наборы (`mdi`, `heroicons`) в продуктовых UI-сценариях заменяются на проектные `i-*` при первой возможности; допустимы только точечные исключения для брендовых/интеграционных случаев.

### CSS Modules

Компоненты используют CSS Modules для изоляции стилей. Это означает, что классы автоматически получают уникальные имена, предотвращая конфликты стилей между компонентами.

**Использование в компонентах:**
```vue
<template>
  <div :class="$style.wrapper">
    <!-- содержимое -->
  </div>
</template>

<style module lang="scss">
.wrapper {
  padding: rem(20);
  background-color: var(--primary);
}
</style>
```

### SCSS функции и миксины

Проект включает набор SCSS утилит в `app/assets/styles/tools/`:

- **Функции** (`_functions.scss`) - функции для работы с единицами измерения (например, `rem()`)
- **Миксины** (`_mixins.scss`) - переиспользуемые блоки стилей

### Базовые стили

Глобальные стили определены в `app/assets/styles/base/`:
- `_global.scss` - глобальные стили
- `_fonts.scss` - настройки шрифтов
- `_booking-input.scss` - стили для элементов форм бронирования

### Структура файлов стилей

```
app/assets/styles/
├── base/              # Базовые стили
├── tools/             # SCSS функции и миксины
├── variables/         # Переменные (цвета, размеры, breakpoints)
└── main.scss          # Главный файл стилей
```

### Рекомендации

1. **Всегда используйте `rem()`** для размеров вместо пикселей
2. **Используйте CSS переменные** для цветов и других значений из дизайн-системы
3. **Применяйте CSS Modules** для изоляции стилей компонентов
4. **Следуйте breakpoints** из `resolutions.scss` для адаптивности
5. **Используйте переменные из `_colors.scss`** вместо хардкода цветов
6. **Импортируйте переменные через `@use`** с правильными алиасами (`size` для resolutions, `z` для z-index)
7. **Используйте функцию `z.z()`** для z-index значений вместо хардкода чисел
8. **Используйте компонент `UIcon`** с префиксом `i-` для иконок из `app/assets/icons`
